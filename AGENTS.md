# Agent Notes

This repository is a VS Code / GitHub Copilot prompt pack for academic navigation.

Product name: Educational Study GHCP Harness (ES)
Product command prefix: `/es-*`
Concierge command: `/es-buddy`

Core mission:

- Map the continent.
- Identify mountain ranges.
- Choose trailheads.
- Ground claims in sources.
- Extract load-bearing fundamentals.
- Build competence through practice.
- Audit false confidence.
- Advance with bounded next actions.

Do not optimize for impressive summaries. Optimize for demonstrated competence.

## Three faces: Atlas, Dojo, Forge

Educational Study GHCP Harness operates as one substrate with three diagnostic faces (full design in `docs/three-faces.md`):

- **Atlas** — _map_. Mode: wander. Orientation work. Light commits, no branches required. Commands: `/es-domain`, `/es-atlas`, `/es-substrate`, `/es-frontier-cones`, `/es-anti-rabbithole`, `/es-goodenough`, `/es-prereqs`.
- **Dojo** — _train_. Mode: study. Competence work. Real commits with provenance; gap ledger (`notes/gap-ledger.md`) tracks weaknesses across sessions; audits gate promotion to `grounded`. Commands: `/es-problem`, `/es-solve`, `/es-drill`, `/es-worked`, `/es-transfer`, `/es-iwrong`, `/es-explain-back`, `/es-calibrate`, `/es-reach`. The Gowers loop is `/es-reach`: it reads the gap ledger and proposes the smallest drill + hardest reachable problem.
- **Forge** — _make_. Mode: synth. Frontier work. **Branched by default** to `explore/<topic>` when (a) the work contradicts a `grounded` page, or (b) it introduces a claim with no Tier 0–2 source. Adversarial review (`/es-falsify`, `/es-audit`) gates merge to `main`. Commands: `/es-falsify`, `/es-steelman`, `/es-contradiction`, `/es-blend`, `/es-tribal`, `/es-lineage`. Failed Forge branches **merge back as `iwrong(...)` commits** — dead ends are preserved per the non-destructive history rule.

The buddy (`/es-buddy`) is the **mode router**. It reads `git log`, `STATE.md`, the active goal, and the gap ledger, then diagnoses the active face and proposes the lightest appropriate next move. Do not nag the user with commit prompts in Atlas; do not let Dojo work proceed without provenance; do not let Forge branches merge to `main` without adversarial review.

`STATE.md` at the repo root is the **legibility primitive**. It is regenerated by `/es-state`, never hand-edited, and is the single file an agent or reader should read first to bootstrap context.

## Repo layers (schema for the LLM)

This repo is also a three-layer compounding-knowledge substrate (per `docs/wiki-integration.md`):

- `raw/` — immutable sources. The agent **reads** from here; **never writes** here.
- `wiki/` — LLM-maintained markdown (entity / concept / source / comparison pages). Patch-only after a page reaches `status: grounded`. Wholesale rewrites require a `/es-update-atlas` pass and a `wiki/log.md` entry.
- `wiki/index.md` — catalog. Updated on every `/es-ingest`. Read this first when answering questions.
- `wiki/log.md` — append-only timeline. Format: `## [YYYY-MM-DD] <op> | <subject>`. Never edit historical entries.
- `wiki/reports/` — `/es-lint` and `/es-audit` outputs.
- `maps/`, `notes/`, `papers/`, `problems/` — per-topic / per-paper / per-problem artifacts as before.

## State management: git is the database

This repo has no runtime, no DB, and no separate state store. **Git is the state machine.** Every meaningful change is a commit; every commit is a row in the audit log. The agent's job is to keep markdown and git in lockstep.

1. **Read before acting.** Before answering a question about prior state, run `git log --oneline -20`, then `git log --oneline -- <path>` for any path you intend to edit. Then read `wiki/index.md` and the relevant section of `wiki/log.md`. Only then proceed.
2. **One command, one commit (proposed).** After applying file edits from a `/es-*` command, propose a conventional commit (type, scope, summary, optional body). Do not run `git commit` unless the user explicitly asks. The user stages and commits.
3. **`wiki/log.md` mirrors git.** When you append a `wiki/log.md` entry, the corresponding commit message must use the same `<type>(<subject>): <summary>` form. If the two disagree later, **git wins**; reconcile `wiki/log.md` to match and commit `chore(reconcile): ...`.
4. **History is append-only.** Never propose `git reset --hard`, `git push --force`, `git rebase`, `git commit --amend` on shared history, or any destructive rewrite. To undo, use `git revert`. Failed experiments stay in the log so the next session does not repeat them.
5. **Promotions and demotions are commits.** Flipping `status: draft → grounded` requires a commit with body containing the falsify and audit evidence. Demotions require a commit with body containing the reason. No silent status changes.
6. **Branches are study lines.** Speculative deep dives go on `explore/<topic>` branches. `main` is the audited spine. Merge only after `/es-audit` passes.
7. **Context recovery on resume.** When a session resumes (e.g. `/es-continue`), the first action is `git log --oneline -20`, then `wiki/log.md` tail, then `wiki/index.md`. State your understanding of where the previous session ended before proposing the next action.

The full conventional-commit type table lives in `README.md` under "Commit message convention." Use those types verbatim.

## Load-bearing rules

1. **Markdown is truth.** If it matters, it is a file. No claim lives only in chat.
2. **Patch, never regenerate** grounded pages. Surgical edits with reasons. Escalate wholesale rewrites as CRITICAL in `wiki/reports/`.
3. **Canonical query as gospel.** Persist verbatim user goals to `notes/<goal>-query.md` and re-read them on every step.
4. **Provenance breadcrumbs.** Every wiki page lists `suggested-by:` in frontmatter. `/es-lint` flags disconnected components.
5. **Claim-level provenance** uses `^[raw/<file>:<lines-or-section>]` immediately after the claim.
6. **Academic APIs before web search** for research-grade claims (Semantic Scholar, arXiv, OpenAlex, PubMed) before generic web.
7. **Pre-promotion adversarial review.** Before flipping `status: draft` → `grounded`, run `/es-audit` and `/es-steelman`.
8. **Lint is structural, not factual.** Never certify correctness; only certify that the structural prerequisites for human evaluation are in place.
9. **Wiki growth without practice is failure.** If the log shows ingests/queries with no `/es-practice` or `/es-drill` between them, surface it.

## Obsidian-compatible conventions

Wiki pages use `[[wikilinks]]`, YAML frontmatter (Dataview-queryable), and `^[raw/...]` provenance markers. The repo is openable as an Obsidian vault with no conversion.

## Scholarly extensions

Atop the substrate, Educational Study GHCP Harness carries layers for serious academic work. Index: `docs/scholarly-extensions.md`.

- **Bibliography:** `wiki/bib/<key>.md` (BibTeX/CSL-JSON). Commands: `/es-cite`, `/es-export`. Template: `templates/citation.md`.
- **Canonical query:** `notes/<slug>-query.md`. Pinned by `/es-goal` and re-read every step.
- **Contradictions register:** `wiki/contradictions.md` (append-only). Command: `/es-contradiction`. Template: `templates/contradiction.md`.
- **Adversarial review:** `/es-falsify` (red-team), `/es-tribal` (single-source folklore), `/es-explain-back` (Feynman drill). Pre-promotion gates.
- **Pedagogy:** `/es-worked` (Sweller-style annotated examples), `/es-transfer` (cross-domain pattern test). Templates: `worked-example.md`, etc.
- **Reflection / calibration:** `/es-decision` (decision journal), `/es-calibrate` (Brier score), `/es-iwrong` (doubt ledger). Files: `notes/decision-journal.md`, `notes/i-could-be-wrong.md`.
- **Lineage:** `/es-lineage` builds intellectual genealogy on entity pages. Template: `lineage.md`.
- **Marginalia:** `wiki/source/<source>-marginalia.md` — section-level glosses on raw sources. Command: `/es-marginalia`.
- **Style:** `notes/style.md` — voice/density schema all explainer commands read first. Edit via `/es-style`.
- **Field layers:** discipline-specific templates (`proof.md`, `case-brief.md`, `experiment.md`, `source-position.md`). See `docs/field-layers.md`.
- **Academic API discipline:** `/es-fetch` emits a deterministic Semantic Scholar / arXiv / OpenAlex / PubMed / Crossref / CourtListener search plan **before** generic web search. See `docs/academic-apis.md`.
- **Graph & dashboard:** `/es-graph` (paths, centrality, islands, cycles over the markdown), `/es-stats` (corpus health, drift, practice-vs-consumption ratio).

Provenance scoring: `provenance-score: 0..1` and `time-spent: <minutes>` are now first-class frontmatter fields. `/es-lint` computes the score; `/es-stats` reports thinness.

## What is deliberately out of scope

- Spaced recall (handled by Obsidian Spaced Repetition / Anki externally).
- Embedding indexes, OCR, multi-agent debate, automatic Bayesian curriculum routing — these require runtime beyond a prompt pack and would violate "markdown is truth."
